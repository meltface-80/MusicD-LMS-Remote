Logs and reporting a problem

A report with what you did, what happened, and the log from that moment is usually enough to fix it. Open an issue on GitHub.

The server's log

docker logs --since 30m musicd-lms-remote

The same lines are kept in a rotating file in the data volume, logs/musicd.log. For more detail, set LOG_LEVEL=debug on the container. Mallard's This phone sends its own player's events here too, so a problem playing on the phone shows in this log:

docker logs --since 10m musicd-lms-remote 2>&1 | grep -iE "relay|phone"

When Lyrion stops answering

The server notes every time Lyrion stops answering and comes back — how long it was gone, and what the server was asking it at that moment. Open http://<server>:3390/api/lms/outages after it happens and send what it shows, with Lyrion's own server.log.

What to include

  • The version: Settings → System (server), and Mallard's in its Settings → System.
  • What you did and what you expected, and when (the time helps find the log lines).
  • The log lines from that time, and a screenshot if it's something you see.
